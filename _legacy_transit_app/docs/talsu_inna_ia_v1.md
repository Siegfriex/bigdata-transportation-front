# 탈수있나 IA 문서 v1

**문서 유형:** Information Architecture Document  
**서비스명:** 탈수있나  
**플랫폼:** Mobile Web App 중심, Mobile App 확장 가능, 운영/관리자 PC Web 별도  
**버전:** v1.0  
**작성 기준:** 기능 ID, 화면 ID, Depth 1~3, 중요도, 구현 대상, 작업 요소, 관리자 연동, 정책 ID, 기능 정의

---

## 0. 문서 목적

본 문서는 이전에 도출한 **탈수있나 기능명세 v1**을 기준으로, 화면·기능·개발 범위를 IA 단위로 재정렬한 문서다.  
레퍼런스 IA의 구조를 차용하되, 차량/딜러 도메인이 아니라 **대중교통 지도형 AI 리포트 서비스**에 맞게 재구성했다.

본 IA는 다음 산출물의 기준으로 사용한다.

1. 화면 목록 정의
2. 기능 ID 체계 관리
3. Figma/FigJam IA 보드 작성
4. 프론트엔드 라우팅 구조 정의
5. 백엔드 API 기능 단위 정의
6. 디자인·퍼블리싱·개발 작업 범위 산정
7. MVP 우선순위 관리

---

## 1. IA 작성 기준

레퍼런스는 `기능 ID`, `화면 ID`, `Depth 1`, `Depth 2`, `Depth 3`, `중요도`, `구현 대상`, `작업 요소`, `관리자 연동`, `정책 ID`, `기능 정의`를 기준으로 기능을 분해한다.  
탈수있나 IA도 동일한 구조를 따르되, 다음 기준으로 변환했다.

| 구분 | 적용 기준 |
|---|---|
| 기능 ID | `TALS-ia-{module}-{number}` 형식 |
| 화면 ID | PRD/FSD에서 정의한 화면 ID 사용 |
| Depth 1 | 대분류 기능군 |
| Depth 2 | 세부 기능 영역 |
| Depth 3 | 실제 사용자 또는 시스템 기능 |
| 중요도 | 상 / 중 / 하 |
| 구현 대상 | PC Web / Mobile Web / Mobile App |
| 작업 요소 | 디자인 / 퍼블리싱 / 개발 |
| 관리자 연동 | 운영자 또는 관리자 기능 필요 여부 |
| 관련 정책 ID | 기능별 정책 또는 예외처리 기준 ID |
| 기능 정의 | 사용자가 수행하거나 시스템이 처리하는 기능 정의 |

```text
A. 회원가입/인증

H. 실패복구 플랜

J. 리포트 아카이브
K. 설정/데이터 안내
L. 알림/공지

N. 네비게이션 구성
```

## 7. IA 설계 메모

1. **지도와 AI 챗은 병렬 진입점이다.** 사용자는 지도에서 직접 조건을 입력할 수도 있고, AI 챗에서 자연어로 질문할 수도 있다.
2. **모든 핵심 플로우는 리포트로 수렴한다.** 탑승가능성, 칸별 생존, 마감도착, 실패복구는 모두 최종적으로 리포트 화면에서 판단값을 제공한다.
3. **데이터 처리 기능은 사용자 화면과 분리한다.** 실시간 데이터 조회, 패턴 데이터 처리, 데이터 신뢰도 배지는 별도 Depth 1로 관리한다.
4. **운영/관리자 기능은 MVP 화면과 분리한다.** 사용자용 Mobile Web과 운영자용 PC Web을 IA상에서 분리해 설계한다.
5. **추정값과 실시간값은 IA 단계에서부터 구분한다.** 서비스 신뢰도와 법적 리스크 관리를 위해 데이터 유형 배지를 별도 기능으로 둔다.
