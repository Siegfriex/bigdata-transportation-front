# PRD: 탈수있나

**문서 유형:** Product Requirements Document  
**서비스 유형:** B2C 지도형 웹앱 + 지도 기반 챗봇 + 이동 판단 리포트  
**대회 맥락:** 2026 국토교통 데이터 활용 경진대회 제품·서비스 개발 분야  
**버전:** v0.1  
**작성일:** 2026-05-26  
**핵심 키워드:** 탑승가능성 / 마감도착 / 실패복구

## 0. Executive Summary

**탈수있나**는 수도권 대중교통 이용자가 출근, 퇴근, 막차, 지각 위기 상황에서 “빠른 길”이 아니라 **실제로 탈 수 있고, 정해진 시간 안에 도착 가능하며, 실패 시 복구 가능한 길**을 선택하도록 돕는 지도형 AI 리포트 웹앱이다.

기존 지도앱은 주로 최단시간 경로를 제시한다. 그러나 실제 사용자는 “이번 버스를 탈 수 있는가”, “이번 지하철을 보내고 다음 열차를 타야 하는가”, “어느 칸에 타야 덜 붐비는가”, “9시까지 도착하려면 택시·따릉이·지하철을 어떻게 조합해야 하는가”, “막차를 놓치면 어떤 플랜 B가 있는가”를 알고 싶어 한다.

**탈수있나**는 버스 잔여좌석·차내혼잡도, 지하철 혼잡도, 빠른하차·환승 정보, 따릉이 실시간 대여정보, GTFS, 교통카드 기반 승하차 패턴을 결합해 사용자의 현재 상황에 맞는 **지도 기반 의사결정 리포트**를 제공한다.

## 2. 문제 정의

### 2.1 사용자의 실제 문제

대중교통 이용자는 단순히 경로를 모르는 것이 아니다. 대부분 사용자는 자신의 반복 통근 경로를 이미 알고 있다. 문제는 그 경로가 **오늘, 지금, 실제로 작동하는지**다.

핵심 문제는 네 가지다.

1. **탑승 불확실성**  
   버스나 지하철이 와도 혼잡하거나 좌석이 없어 실제로 탈 수 없을 수 있다.

2. **혼잡 기반 의사결정 부재**  
   기존 지도앱은 빠른 경로를 추천하지만, 덜 붐비는 경로나 덜 힘든 칸을 판단해주지 않는다.

3. **마감시각 기반 조합 탐색 부족**  
   사용자가 9시까지 출근해야 하는데 일반 대중교통만으로는 지각이라면, 택시·따릉이·지하철·버스를 섞은 현실적 조합이 필요하다.

4. **실패 복구 부재**  
   막차 실패, 환승 실패, 탑승 실패 상황에서 플랜 B/C를 찾기 어렵다.

### 2.2 해결해야 할 핵심 질문

- 이번 버스나 지하철을 실제로 탈 수 있는가?
- 다음 차를 기다리는 것이 더 나은가?
- 지하철에서는 어느 칸에 타야 덜 붐비고 환승도 가능한가?
- 정해진 시간 안에 도착하려면 어떤 수단을 어떻게 조합해야 하는가?
- 막차나 환승에 실패하면 어떤 대안이 있는가?

## 7. 핵심 기능명세

---

## 7.1 F1. 탑승가능성 리포트

### 7.1.1 기능 정의

버스와 지하철을 같은 대중교통 객체로 보고, 사용자가 현재 위치에서 **이번 차를 탈 수 있는지, 다음 차를 기다리는 것이 나은지, 대체 경로가 필요한지** 판단할 수 있게 한다.

### 7.1.2 사용자 스토리

- 나는 사당역에서 경기 광역버스를 기다린다. 이번 버스가 와도 좌석이 없을까 봐 불안하다. 앱이 이번 차와 다음 차를 비교해줬으면 한다.
- 나는 9호선 급행을 기다린다. 이번 열차가 너무 붐비면 다음 일반열차를 탈지 판단하고 싶다.

### 7.1.3 포함 기능

| 세부 기능 | 설명 |
|---|---|
| 이번 차 탈 수 있나 | 현재 도착 예정 차량·열차의 탑승 가능성 표시 |
| 다음 차가 더 낫나 | 첫 번째 차와 두 번째 차 비교 |
| 잔여좌석 표시 | 경기도 버스 등 직접값이 있는 경우 표시 |
| 혼잡도 표시 | 차내혼잡도 또는 예측 혼잡도 표시 |
| 추천 행동 | 이번 차 탑승, 다음 차 대기, 대체 경로 이동 |

### 7.1.4 데이터 요구사항

| 데이터 | 출처 후보 | 실시간성 | 포맷 | 처리 방식 | 용도 |
|---|---|---:|---|---|---|
| 경기도 버스도착정보 | GBIS | 실시간 | XML/JSON | 직접 사용 | 잔여좌석, 차내혼잡도, 도착시간 |
| 서울 버스도착정보 | 서울 열린데이터광장 | 실시간 | API | 직접 사용 | 도착예정, 현재위치 |
| 서울 버스위치정보 | 서울 열린데이터광장 | 실시간 | API | 직접 사용 | 차량 위치 |
| 버스 승하차 패턴 | 서울 열린데이터광장, 교통카드 통계 | 비실시간 | CSV/API | 패턴화 | 서울 버스 혼잡 추정 |
| 지하철 혼잡도 | 서울교통공사, 9호선 | 비실시간 | CSV/파일 | 예측 모델 | 역·방향·시간대 혼잡 |
| 지하철 도착정보 | 서울 열린데이터광장 | 실시간 | API | 직접 사용 | 열차 도착 판단 |

### 7.1.5 데이터 처리 범위

| 처리 유형 | 내용 |
|---|---|
| 그대로 가져오는 데이터 | 경기도 버스 잔여좌석, 차내혼잡도, 도착예정시간 |
| 조합 필요한 데이터 | 서울 버스 도착정보 + 위치정보 + 승하차 패턴 |
| 패턴화 필요한 데이터 | 노선·정류장·요일·시간대별 승차/하차 |
| 예측 대상 | 지하철 탑승 가능성, 서울 버스 예상 혼잡도 |
| 최적해 산출 대상 | 이번 차 vs 다음 차 vs 대체 경로 |

## 7.2 F2. 칸별 생존가이드

### 7.2.1 기능 정의

지하철 이용자가 **어느 칸에 타야 덜 붐비고, 환승·하차도 실패하지 않는지** 추천한다.

MVP에서는 실시간 칸별 인원 실측이 아니라, **공공데이터 기반 칸별 생존점수**로 구현한다.

### 7.2.2 사용자 스토리

- 나는 9호선 급행을 탄다. 빠른 환승 칸은 알지만 너무 붐빈다. 조금 떨어져도 덜 힘든 칸을 알고 싶다.
- 나는 짐이 많다. 빠른 하차보다 덜 붐비는 칸이 더 중요하다.

### 7.2.3 포함 기능

| 세부 기능 | 설명 |
|---|---|
| 빠른 하차 칸 | 하차역 출구·계단과 가까운 칸 추천 |
| 빠른 환승 칸 | 환승 통로와 가까운 칸 추천 |
| 혼잡 회피 칸 | 빠른 칸에서 1~2칸 떨어진 대안 추천 |
| 회피 칸 | 환승객·출구 쏠림이 큰 칸 경고 |
| 선호별 추천 | 빠른 환승, 덜 붐빔, 교통약자, 짐 많음 |

### 7.2.4 데이터 요구사항

| 데이터 | 출처 후보 | 실시간성 | 포맷 | 처리 방식 | 용도 |
|---|---|---:|---|---|---|
| 빠른하차정보 | 서울교통공사, 공공데이터 | 정적/준정적 | API/파일 | 직접 사용 | 하차 칸·문 번호 |
| 빠른환승정보 | 국토교통부, 공공데이터 | 정적/준정적 | CSV/API | 직접 사용 | 환승 칸·문 번호 |
| 지하철 혼잡도 | 서울교통공사, 9호선 | 비실시간 | CSV/파일 | 패턴화 | 시간대별 기본 혼잡 압력 |
| 역 구조 정보 | 공공데이터, 운영기관 | 정적 | 파일/지도데이터 | 조합 | 계단, 출구, 엘리베이터 위치 |

## 12. 알고리즘 및 모델링

### 12.1 탑승가능성 스코어

```text
탑승가능성 =
직접 혼잡값 또는 예측 혼잡값
+ 잔여좌석
+ 도착예정시간
+ 배차간격
+ 정류장 또는 역의 시간대별 수요
+ 사용자 혼잡 민감도
```

### 12.2 칸별 생존점수

```text
칸별 생존점수 =
하차 편의 점수
+ 환승 편의 점수
+ 혼잡 회피 점수
+ 사용자 선호 점수
- 출구 쏠림 패널티
- 환승 집중 패널티
- 고혼잡 시간대 패널티
```

### 12.3 마감도착 최적화

```text
목표:
도착시각 <= 마감시각

제약:
택시비 <= 사용자 예산
도보시간 <= 허용 도보시간
자전거 이용 가능 여부 == 사용자 설정
혼잡도 <= 허용 수준
환승 실패확률 <= 허용 위험도

최적화 우선순위:
1. 도착 성공
2. 실패 리스크 최소
3. 비용 최소
4. 체력 부담 최소
```

### 12.4 실패복구 플랜 생성

```text
실패복구 플랜 =
현재 대중교통으로 최대 이동 가능한 지점 탐색
+ 심야버스 또는 잔여 운행 탐색
+ 도보 연결 가능성 계산
+ 최소 택시 구간 산출
+ 첫차 대기 또는 안전 거점 후보 탐색
```

### 12.5 AI 활용 계획

| 모델/도구 | 기능 | 목적 |
|---|---|---|
| LightGBM/XGBoost | 탑승가능성 예측 | 서울 버스·지하철 혼잡 기반 탑승 가능성 추정 |
| LSTM/GRU | 혼잡 예보 | 시간대별 혼잡 패턴 예측 |
| Bayesian Update | 실패확률 | 환승·막차 실패 가능성 추정 |
| Graph Search | 경로 후보 탐색 | 대중교통·도보·따릉이·택시 조합 탐색 |
| Multi-objective Optimization | 마감도착 플랜 | 시간·비용·혼잡·위험 동시 최적화 |
| GPT/RAG | 챗봇 리포트 | 지도 데이터와 추천 근거를 자연어로 설명 |

## 16. 개인정보·보안·윤리

### 16.1 개인정보 원칙

| 원칙 | 설명 |
|---|---|
| 최소 수집 | 위치는 기능 수행 시에만 사용 |
| 로컬 우선 | 집/회사/학교는 가능하면 로컬 저장 |
| 명시적 동의 | 위치 권한, 알림 권한, 루틴 저장은 별도 동의 |
| 추정값 고지 | 혼잡도·도착시간·실패확률은 예측값임을 표시 |
| 민감 추적 금지 | 장기 이동 이력 저장을 기본값으로 하지 않음 |

### 16.2 윤리적 표현

- “위험지역”처럼 낙인 효과가 있는 표현을 피한다.
- “불가능”보다는 “현재 조건에서는 성공 가능성이 낮음”으로 표현한다.
- 추정 모델 결과는 확정값처럼 표시하지 않는다.
- 실시간 데이터가 없는 경우 “예상”, “추정”, “패턴 기반”을 명시한다.

## 21. 제출용 핵심 문장

**탈수있나**는 수도권 대중교통 이용자를 위해 버스 잔여좌석·차내혼잡도, 지하철 혼잡도, 빠른하차·환승 정보, 따릉이 실시간 대여정보, 교통카드 기반 이동 패턴을 결합하여 **“빠른 경로”가 아니라 “실제로 탈 수 있고 제시간에 도착 가능한 이동 플랜”**을 제시하는 지도형 AI 리포트 웹앱이다.

핵심 기능은 네 가지다.

1. **탑승가능성 리포트** — 이번 버스·지하철을 탈 수 있는지 판단  
2. **칸별 생존가이드** — 어느 칸에 타야 덜 힘든지 추천  
3. **마감도착 플랜** — 지각 위기에서 가능한 모든 수단 조합 산출  
4. **실패복구 플랜** — 막차·환승·혼잡 실패 시 플랜 B/C 제공
